# Резервный медиа-хост

Второй хост с тем же медиа-стеком (vrelay + coturn). Он держит эфир, пока основной медиа-хост болен. Основной остаётся основным: резервный выключили, и эфир сам вернулся на основной.

Поднят 2026-11-04, когда основной (185.76.241.50) завис у хостера. Подробности разбора — в конце.

## Почему vrelay работает только на одном хосте

`findVrelayAgent()` в `apps/server/tree.js` берёт агента, который подключился первым (порядок вставки в `peers`). С двумя подключёнными агентами каждый перезапуск прода (любой деплой сервера) заново решает, кто главный, и выиграть может агент на больном хосте. Поэтому, пока жив резервный, vrelay основного стоит, а поднимает его сторож.

## Раскладка

|          | основной                                         | резервный      |
|----------|--------------------------------------------------|----------------|
| хост     | 185.76.241.50                                    | 138.16.160.122 |
| vrelay   | остановлен (`docker compose stop`), поднимает сторож | работает   |
| coturn   | работает                                         | работает       |

- Прод `.env`: `TURN_URLS` — сначала резервный, потом основной; `STUN_URLS` — резервный и Google. Клиенты пропускают недоступный TURN, поэтому основной в списке нужен для возврата без перезапуска прода. Бэкап `.env` до правки: `/opt/voice/.env.bak-fallback-20261103T235634`.
- Резервный поставлен так же, как основной, по `deploy/vrelay-remote/`: тот же `docker-compose.yml`, `turnserver.conf`, `99-relayapp-udp.conf` в `/etc/sysctl.d/`. В `.env` те же `TURN_SECRET` и `VRELAY_AUTH_SECRET`, что на проде (сверять sha256, не печатать), `TURN_LISTEN_IP` — свой публичный IP. На 4 vCPU стоит `VRELAY_MAX_TRANSCODES=2`.
- На резервном SSH пускает только по ключу (`/etc/ssh/sshd_config.d/10-relay-keys-only.conf`).

## Сторож на основном

Файлы рядом с этим README. Установка на основной хост:

```sh
install -m 755 relay-vrelay-standby.sh /usr/local/sbin/
install -m 644 relay-vrelay-standby.service relay-vrelay-standby.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now relay-vrelay-standby.timer
```

Раз в 30 секунд:

- vrelay на этом хосте уже работает — ничего не делает;
- резервный отвечает по TCP 3478 (его coturn) — ничего не делает;
- резервный молчит, а прод отвечает 200 — считает подряд идущие промахи; на третьем (~1,5 минуты) делает `docker start vrelay-vrelay-1`;
- молчит и прод — значит, сломана сеть самого хоста, ждёт.

Обратно vrelay сторож не гасит. Журнал: `journalctl -u relay-vrelay-standby`.

## Как вернуться на основной

1. Выключить резервный хост (или `docker compose stop vrelay` на нём).
2. Подождать ~1,5 минуты: сторож поднимет vrelay основного, тот подключится к проду и встанет во все живые эфиры (`onVrelayHello`).
3. Не срочно: убрать резервный из `TURN_URLS`/`STUN_URLS` на проде и пересоздать `token`; на основном `systemctl disable --now relay-vrelay-standby.timer`.

Если возвращаешь руками, порядок тот же: сначала гасить резервный, потом поднимать основной. Иначе подключены два агента, и главным остаётся резервный.

## Чего не делать, пока работает резервный

- Не пушить в `apps/relay/`, `apps/relay-core/`, `deploy/vrelay-remote/`. Job `deploy_media` катит vrelay на хост из секретов `MEDIA_SSH_*`, то есть на основной, и запускает его там. Получатся два агента.
- Обычные пуши веба и сервера безопасны: прод перезапустится, и подключится единственный агент — резервный.

## Как поняли, что болен хост, а не код (2026-11-03)

- Потери на входе vrelay у всех вещателей одновременно, включая аудио (15–50% разрывов RTP). Независимые аплинки так синхронно не сыплются — виноват приёмник.
- `vmstat 1` на медиа-хосте: `st` 30–60%, гипервизор отбирает CPU у виртуалки. На проде в то же время `st` 0–1%.
- `mtr` с медиа-хоста до своего шлюза: ~50 мс и потери; растут `UdpRcvbufErrors`.
- `journalctl -k`: `soft lockup - CPU#N stuck for 26–80s`, `rcu_preempt kthread starved`, сторож systemd убивает journald/networkd/logind.
- Сам эпизод: с 23:17 до 23:28 хост не отвечал вообще, хотя шлюз провайдера был жив. Агент vrelay отвалился по heartbeat и сам вернулся, но хост остался полуживым.
