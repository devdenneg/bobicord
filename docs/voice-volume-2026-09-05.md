# Кратковременные скачки индивидуальной громкости

## Воспроизведённая причина

LiveKit 2.20.0 пересоздавал WebAudio-граф при каждом `Room.startAudio()`:
`acquireAudioContext` повторно передавал тот же контекст участникам. Новый
`RemoteAudioTrack` gain подключался к выходу со стандартным значением 1, и только
затем получал `setTargetAtTime(saved, 0, 0.1)`. Поэтому сохранённая тихая громкость
возвращалась не сразу: сначала проходил громкий фрагмент. Проверка `if (saved)`
также теряла значение 0. Аналогичный риск существовал при переподключении трека.

Дополнительно Engine применял индивидуальную громкость после `attach`, когда
новый граф уже мог воспроизводить звук. Повторный HTML attach мог оставлять
второй аудиоэлемент незаглушённым, в обход WebAudio-регулятора.

Это воспроизведение механизма в коде, а не доказательство по записи конкретного
пользовательского звонка. Аппаратное прослушивание на устройствах не выполнялось.

## Изменение

- Engine задаёт громкость до attach микрофона и звука трансляции, включая
  восстановление воспроизведения. Используется настройка голосового сервера,
  даже когда пользователь смотрит другой сервер.
- Новый gain получает сохранённое значение, включая 0, до подключения выхода.
- Передача уже используемого AudioContext не пересоздаёт живой граф. Настоящее
  возобновление контекста, смена контекста и переподключение продолжают работать.
- Все смешиваемые HTML-элементы остаются беззвучными, в том числе при повторном
  attach и `Room.startAudio`; служебный элемент разблокировки iOS исключён.

Нет новых таймеров, сетевых запросов, ожиданий или дополнительных аудиоузлов.
При повторной передаче того же контекста тест проверяет отсутствие новых gain.
Громкости микрофона и трансляции независимы; master, локальный mute и deafen
сохраняют своё назначение.

## Воспроизводимая установка

Версия SDK закреплена на 2.20.0. `scripts/patch-livekit-audio.mjs` применяет
узкое исправление к ESM-export, который используют Vite и desktop webview.
UMD/CommonJS и исходники пакета не изменяются. Проверяются версия, путь export,
точные исходный и исправленный SHA-256; повторный запуск идемпотентен. При иной
версии или постороннем изменении установка останавливается, не перезаписывая его.
После обновления SDK патч нужно пересмотреть и удалить, когда upstream проходит
контрактные тесты.

`postinstall` выполняет патч при `npm ci`; Docker копирует скрипт до установки.
`predev` и `test:volume` проверяют наличие исправленного артефакта, а production
build включает `test:volume`.

При проверке найдены прежние неотслеживаемые локальные изменения SDK, которых
нет в чистом npm-пакете. Они не включены в эту задачу и не удалены. Поэтому
окончательная проверка выполнена в отдельной директории с чистым `npm ci`, без
копирования локальных `.env`. Проверка целостности в исходной рабочей директории
намеренно отклоняет такой изменённый SDK; перед его переустановкой нужно
согласовать сохранение чужих локальных изменений.

## Проверки

- Исходный регрессионный набор на непатченном SDK: 16 ошибок из 19 тестов.
- Итоговый расширенный набор на чисто установленном и исправленном SDK:
  `node --test src/remoteAudioVolume.test.mjs` — 23/23.
- Actual Engine: проверка установки громкости до attach падает на прежнем
  Engine и проходит на исправленном; mute, master, deafen, восстановление,
  отдельная трансляция и просмотр другого сервера покрыты.
- Чистый `npm ci --offline --no-audit --no-fund`, повторная проверка патча и
  полный `npm run build` (все наборы, TypeScript, Vite) — успешно.

Тесты исполняют настоящий ESM SDK; MediaStream, DOM и WebAudio заменены
детерминированными моделями. Модель AudioParam учитывает плавное затухание,
проверяется уровень в момент подключения и после него, а не только сохранённое
число в настройке. Проверка на реальном устройстве после выпуска всё ещё нужна.

Отдельные гонки сохранения настроек при быстром переключении серверов в этой
правке не менялись: они могут вызывать стойкий сброс настройки, но не описанный
кратковременный скачок при восстановлении воспроизведения.
