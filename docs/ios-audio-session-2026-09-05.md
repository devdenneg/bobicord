# Повторный сбой микрофона при сворачивании iOS

Пользователь воспроизвёл системное выключение микрофона уже после direct-capture обновления.
Предыдущая правка отделила передачу от Web Audio, но этот сценарий на устройстве не решила.
Системный индикатор при включённой кнопке приложения указывает на возможное прерывание
источника. Это гипотеза: enabled, muted и слышимость у другого участника — разные признаки.

## Первичные источники и границы

- [WebKit 236509](https://bugs.webkit.org/show_bug.cgi?id=236509) описывает остановку PWA
  capture при сворачивании/Пункте управления. Статус NEW, последнее подтверждение 2022 года:
  совпадение симптомов не доказывает тот же дефект на текущей iOS.
- [DOMAudioSession](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/Modules/audiosession/DOMAudioSession.cpp)
  устанавливает category override для play-and-record; auto снимает override.
- [MediaSessionManagerCocoa](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/platform/audio/cocoa/MediaSessionManagerCocoa.mm)
  без override выбирает категорию по активным источникам. Сам по себе активный микрофон
  уже имеет приоритет над Web Audio; наличие нескольких контекстов не доказывает причину.
- [W3C Media Capture](https://www.w3.org/TR/mediacapture-streams/#media-flow) различает
  пользовательский enabled и системный muted. Клон не обходит системное прерывание.

## Проверяемая мера

На поддерживаемой Apple mobile платформе категория play-and-record удерживается на срок
владения звонком/предпросмотром. Общий счётчик предотвращает сброс категории между
перекрывающимися владельцами; последний освобождает только собственное значение.
Это мера против автоматических переходов категории, а не разрешение на фоновый захват.
Повторяющиеся фоновые getUserMedia, фиктивное воспроизведение и обход mute не добавляются.

Диагностика различает состояние кнопки, raw-track muted/enabled, published enabled и
состояние/тип AudioSession. Изменение источника записывается и при скрытой странице;
само восстановление остаётся на переднем плане. Только фиксированные enum и boolean,
без имён устройств, аудиозаписи и приватных данных системы.

Service worker в репозитории и публичная копия не перехватывают загрузку приложения
из кэша; сервер отдаёт sw.js с no-store. Но уже открытая страница исполняет старый JS
до перезагрузки. Удаление PWA/данных и повторный вход для этой проверки не требуются.

Подтверждение результата возможно только на физическом устройстве: обновлённая страница,
первый вход, речь с собеседником, фон 30–60 секунд, блокировка, Пункт управления, возврат,
mute/deafen, Bluetooth и повторный вход. Отдельно сравнить Safari и запуск с домашнего
экрана. Если iOS всё равно прерывает источник, не объявлять проблему решённой.
